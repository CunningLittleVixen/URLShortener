# Архитектура и модули

Вернуться к [README](../README.md).

## Слои

```text
ui  ───►  core  ◄───  infra
```

`core` не зависит ни от `ui`, ни от `infra`: он описывает правила и интерфейсы, а реализации
подставляются снаружи. `Main` создаёт все объекты и передаёт их друг другу через конструкторы.

## Модули

### core — модель и правила

| Класс | Назначение |
|---|---|
| `Link` | Неизменяемая ссылка (код, адрес, владелец, создана, истекает, лимит, счётчик). Вычисляет `isExpired`, `isLimitReached`, `status`; `withClickRegistered` и `withClickLimit` возвращают копию |
| `LinkStatus` | Состояние ссылки: `ACTIVE`, `LIMIT_REACHED`, `EXPIRED` |
| `LinkService` | Вся логика: создание, переход, правка лимита, удаление, список, очистка, вход, чтение уведомлений; проверка прав владельца |
| `LinkRepository` | Контракт хранилища ссылок: `add`, атомарный `update`, `findByCode`, `findByOwner`, `findAll`, `delete` |
| `Notification`, `NotificationType` | Данные уведомления (владелец, тип, код, адрес, время) и его тип: `LIMIT_REACHED`, `EXPIRED` |
| `NotificationRepository` | Контракт хранилища уведомлений: `add`, `takeAll` (вернуть и удалить), `findAll` |
| `LoginResult` | Результат входа: ссылки, уведомления, признак «пользователь известен» |
| `UrlValidator` | Проверка адреса: только http/https, есть хост, не длиннее 2048 символов |
| `UserIdParser` | Строгий разбор UUID (ровно 36 символов) |
| `CodeGenerator` | Контракт генератора кодов |
| `AppConfig` | Неизменяемая конфигурация, проверяет значения при создании |
| `ServiceException` | Ошибка по вине пользователя: её текст показывается в консоли |

### infra — реализации

| Класс | Назначение |
|---|---|
| `ConfigLoader` | Читает `app.properties` (UTF-8), при ошибке прерывает запуск |
| `RandomCodeGenerator` | Код из 62 символов на `SecureRandom` |
| `InMemoryLinkRepository`, `InMemoryNotificationRepository` | Потокобезопасные хранилища в памяти (`ConcurrentHashMap`) |
| `JsonFileStore` | Чтение списка из JSON и атомарная запись (временный файл и замена) |
| `JsonLinkRepository`, `JsonNotificationRepository` | Обёртки над хранилищами в памяти: читают файл при создании и сохраняют после каждого изменения |
| `JsonMappers` | Настройка Jackson (в файл не попадают вычисляемые значения) |
| `CleanupScheduler` | Запускает очистку при старте и затем с паузой `cleanup.interval`; поток-демон; `stop()` дожидается текущего прохода |

### ui — консоль

| Класс | Назначение |
|---|---|
| `ConsoleApp` | Цикл чтения команд, приглашение, показ уведомлений, перехват непредвиденных ошибок |
| `CommandProcessor` | Разбор строки и выполнение команд, перехват `ServiceException` |
| `Session` | Активный пользователь (только в памяти) |
| `Messages` | Русские тексты: справка, статусы, уведомления, формат времени |
| `Browser`, `DesktopBrowser` | Открытие адреса в браузере; запасной вариант при недоступном рабочем столе |

`Main` — точка входа: читает конфигурацию, создаёт хранилища, сервис и консоль, запускает и
останавливает очистку, включает UTF-8 для ввода и вывода.

## Основные потоки

1. **Создание.** `create` → проверка адреса и лимита → генерация кода → `LinkRepository.add`
   (если код занят, новая попытка) → сохранение в файл.
2. **Переход.** `open` → разбор кода → `LinkRepository.update` проверяет срок и лимит и увеличивает
   счётчик одной атомарной операцией → если лимит достигнут, создаётся уведомление → браузер.
3. **Очистка.** `CleanupScheduler` → `LinkService.removeExpired` → удаление просроченных ссылок →
   уведомление владельцу о каждой.

## Хранение данных

Два файла (пути в `app.properties`): `data/links.json` и `data/notifications.json`.
Формат — массив JSON-объектов, поля совпадают с полями `Link` и `Notification`, время в ISO-8601 (UTC):

```json
[{"code":"aB3xYz","originalUrl":"[https://example.com](https://example.com)","ownerId":"123e4567-e89b-12d3-a456-426614174000",
  "createdAt":"2026-11-08T10:00:00Z","expiresAt":"2026-11-09T10:00:00Z","clickLimit":5,"clickCount":2}]
```

- Запись идёт после каждого изменения: сначала во временный файл, затем атомарная замена.
- Если файл повреждён или не проходит проверки модели (например, лимит 0), запуск
  прекращается с сообщением; файл не изменяется.
- Редактировать файлы вручную можно только при остановленной программе.

## Известные ограничения

- Два файла записываются по отдельности: при аварийном завершении ровно между двумя записями
  возможна потеря одного уведомления.
- Непрочитанные уведомления владельца, который не входит в приложение, остаются в хранилище.
- Файлы рассчитаны на один процесс: две копии программы на одних данных не поддерживаются.
- Конфигурация находится внутри jar: для изменения настроек нужна пересборка.
