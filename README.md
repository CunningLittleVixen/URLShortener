# URL Shortener

[![CI](https://github.com/CunningLittleVixen/URLShortener/actions/workflows/ci.yml/badge.svg)](https://github.com/CunningLittleVixen/URLShortener/actions/workflows/ci.yml)

Консольный сервис коротких ссылок на Java 21. Превращает длинный адрес в короткий вида
`clck.ru/aB3xYz`, ограничивает число переходов и срок жизни ссылки и сообщает владельцу,
когда ссылка перестала работать. Работает локально, без HTTP-сервера и паролей:
пользователь определяется по UUID.

## Возможности

- Короткие ссылки; разные пользователи получают разные коды даже для одного и того же адреса.
- Лимит переходов (от 1 до 1000) с точным подсчётом и блокировкой после исчерпания.
- Срок жизни задаётся конфигурацией (по умолчанию 24 часа), просроченные ссылки удаляются сами.
- Уведомления владельцу, когда лимит исчерпан или срок истёк.
- Несколько пользователей и несколько ссылок у каждого; менять и удалять ссылку может только владелец.
- Переход по короткой ссылке открывает исходный адрес в браузере.
- Данные хранятся в JSON-файлах и сохраняются между запусками.

## Быстрый старт

Нужны JDK 21 (проверка: `java -version`) и Git. Maven устанавливать не нужно, проект
содержит Maven Wrapper; библиотеки скачаются при первой сборке.

```bash
git clone [https://github.com/CunningLittleVixen/URLShortener.git](https://github.com/CunningLittleVixen/URLShortener.git)
cd URLShortener
./mvnw clean package
java -jar target/url-shortener-1.0-SNAPSHOT.jar
```

- Сборка запускает тесты; чтобы пропустить их: `./mvnw clean package -DskipTests`.
- Запускайте программу всегда из одной и той же папки: там создаётся папка `data/` с вашими данными.
- Из IntelliJ IDEA: откройте класс `Main` и нажмите Run рядом с методом `main`.

## Как пользоваться

При запуске вы гость. Первая команда `create` выдаёт ваш UUID и входит под ним.

### Команды

| Команда | Что делает |
|---|---|
| `create <url> [лимит]` | Создаёт короткую ссылку. Гость получает новый UUID, его нужно сохранить. Лимит от 1 до 1000, по умолчанию 1000 |
| `list` | Показывает ваши ссылки: статус, переходы, срок, допустимые границы лимита |
| `open <ссылка>` | Открывает исходный адрес в браузере. Ссылка вида `clck.ru/aB3xYz` или просто код. Доступна и гостю |
| `edit-limit <код> <лимит>` | Меняет лимит действующей ссылки; новый лимит должен быть больше числа уже сделанных переходов |
| `delete <код>` | Удаляет вашу ссылку |
| `whoami` | Показывает ваш UUID |
| `login <uuid>` | Вход по UUID, только из режима гостя |
| `logout` | Выход (режим гостя) |
| `help` | Справка |
| `exit` | Завершение программы (также Ctrl+C или конец ввода) |

Адрес для сокращения: только `http` или `https`, с именем хоста, не длиннее 2048 символов.
Ошибки ввода выводятся сообщением, программа продолжает работу.

## Конфигурация

Параметры лежат в отдельном файле [`src/main/resources/app.properties`](src/main/resources/app.properties)
и читаются при запуске. Время записывается в формате ISO-8601: `PT24H` (24 часа), `PT30M` (30 минут), `PT30S` (30 секунд).

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `link.ttl` | Время жизни ссылки; пользователь изменить его не может | `PT24H` |
| `link.min-limit` / `link.max-limit` | Допустимые границы лимита переходов | `1` / `1000` |
| `link.default-limit` | Лимит, если пользователь его не указал | `1000` |
| `link.code-length` | Длина короткого кода | `6` |
| `link.prefix` | Префикс, показываемый перед кодом | `clck.ru/` |
| `cleanup.interval` | Как часто удаляются просроченные ссылки | `PT1M` |
| `storage.file` | Файл со ссылками | `data/links.json` |
| `storage.notifications-file` | Файл с непрочитанными уведомлениями (должен отличаться от `storage.file`) | `data/notifications.json` |

Чтобы изменить настройки, поправьте файл и пересоберите проект (он копируется в jar при сборке).
При неверном или пропущенном значении (например, `link.ttl=сутки`, отрицательный срок,
минимум больше максимума) программа не запускается и называет причину.

## Правила работы

| Тема | Правило |
|---|---|
| Переходы | Счётчик растёт на 1 атомарно, ни один переход не теряется. Переход засчитывается в момент выдачи адреса, даже если браузер не открылся. Недоступная ссылка блокируется, причина показывается (если их две, называется истёкший срок) |
| Срок жизни | Одинаков для всех, задаётся только конфигурацией. После истечения ссылка недоступна сразу, а удаляется фоновой очисткой (при старте и затем каждые `cleanup.interval`). Исчерпанная ссылка хранится до конца срока |
| Пользователи | Только UUID, без паролей и администратора. `login` работает только из режима гостя. Если все ссылки пользователя истекли и уведомления прочитаны, его UUID становится неизвестным: нужно выполнить `create` |
| Права | Менять лимит и удалять ссылку может только владелец; открыть может любой. Лимит меняется только у действующей ссылки: от «число переходов + 1» до `link.max-limit`; срок и счётчик не меняются |
| Уведомления | Владелец узнаёт об исчерпании лимита (в момент последнего перехода) и об удалении по сроку. Показываются при `login` и после каждой команды, после показа удаляются. Пока владелец не вошёл, они хранятся |
| Данные | Сохраняются после каждого изменения и переживают перезапуск. Активный пользователь не сохраняется: после запуска нужен `login <uuid>` |

## Архитектура и принятые решения

```text
ui  ───►  core  ◄───  infra
Main собирает части вместе (зависимости передаются через конструкторы)
```

- `core` — модель, правила и контракты (интерфейсы хранилищ). Ничего не знает о файлах и консоли.
- `infra` — реализации контрактов: хранилища в памяти и в JSON, чтение конфигурации, генератор кодов, расписание очистки.
- `ui` — консоль: разбор команд, тексты, открытие браузера.
- `Main` — точка входа и единственное место, где создаются и связываются объекты.

| Решение | Причина |
|---|---|
| Неизменяемые `record` для ссылки, уведомления, конфигурации | Объект нельзя изменить случайно, обновление создаёт копию |
| Статус ссылки вычисляется из срока и счётчика, а не хранится | Статус не может разойтись с действительностью |
| Время передаётся через `Clock` | Поведение по времени проверяется тестами без ожидания |
| Счётчик увеличивается атомарно внутри `LinkRepository.update` | Параллельные переходы не теряются, лимит точный |
| Уникальность кода обеспечивает атомарный `LinkRepository.add` | Гарантия, а не вероятность: при совпадении генерируется новый код |
| Права проверяет `LinkService`, а не консоль | Правило нельзя обойти из другого интерфейса |
| Пользователь — это `ownerId` в ссылке | Отдельного списка пользователей не нужно |
| Уведомление хранит данные, а русский текст формирует `ui` | Логика не зависит от формулировок |
| Запись в JSON после каждого изменения через временный файл | При сбое остаётся целый файл, потерь счётчиков нет |
| Повреждённый файл останавливает запуск, не перезаписывается | Данные можно спасти вручную |

Подробное описание каждого модуля, потоков данных и формата файлов: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Тестирование

```bash
./mvnw test            # все тесты
./mvnw verify          # тесты + проверка стиля Spotless (то же запускает CI)
./mvnw spotless:apply  # автоматически исправить оформление
```

В проекте 179 тестов (JUnit):

| Вид | Что проверяет |
|---|---|
| Модульные | Каждый класс отдельно: модель, валидация адреса и UUID, конфигурация, хранилища (в том числе параллельные обновления), планировщик очистки, команды консоли |
| Интеграционные | `ConsoleAppTest` — сквозные сценарии консоли; `ShortenerScenariosTest` — сценарии из задания на настоящих JSON-файлах: уникальные коды для разных пользователей, блокировка по лимиту, удаление по сроку (1 час и 24 часа), уведомления, права владельца, сохранение после перезапуска |

Открытие браузера в тестах заменено поддельным (`FakeBrowser`), время — управляемыми часами,
поэтому тесты не открывают окна и не ждут. Реальное открытие браузера проверено вручную.
GitHub Actions при каждом пуше в `main` запускает сборку, тесты и проверку стиля.

## Соответствие критериям

| Критерий | Как реализовано | Проверка |
|---|---|---|
| 1. Сокращение и уникальность | Код из `link.code-length` символов (A–Z, a–z, 0–9) генерирует `RandomCodeGenerator` на `SecureRandom`. Уникальность обеспечивает атомарный `LinkRepository.add` (до 10 попыток), каждый `create` создаёт новую ссылку, поэтому у разных пользователей коды разные | `RandomCodeGeneratorTest`, `LinkServiceTest`, сценарий «один адрес, два пользователя» |
| 2. Переход из консоли | Команда `open` получает адрес из `LinkService.open` и вызывает `Desktop.getDesktop().browse(...)` (`DesktopBrowser`) после проверки `isDesktopSupported()` и `Action.BROWSE`; при неудаче печатает адрес для ручного открытия | `DesktopBrowserTest`, `CommandProcessorTest`, ручная проверка jar |
| 3. Лимит переходов | Счётчик увеличивается атомарно в `LinkRepository.update`, проверка срока и лимита выполняется в той же операции; заблокированный переход счётчик не меняет | Тесты с параллельными обновлениями (1000 и 100), сценарий «лимит исчерпан» |
| 4. Срок жизни и автоудаление | `link.ttl` из конфигурации; ссылка недоступна сразу по истечении срока; `LinkService.removeExpired` удаляет просроченные, `CleanupScheduler` вызывает его при старте и по расписанию (поток-демон, сбой одного прохода расписание не останавливает) | `LinkServiceTest`, `CleanupSchedulerTest`, сценарий с TTL в 1 час и в 24 часа |
| 5. UUID и права | UUID выдаётся при первом `create` и строго проверяется (`UserIdParser`); владельца проверяет `LinkService` в слое core | `UserIdParserTest`, `LinkServiceTest`, сценарий прав |
| 6. Конфигурация | Все параметры в `app.properties`; `ConfigLoader` читает, `AppConfig` проверяет; при ошибке приложение не запускается и называет причину | `ConfigLoaderTest`, `AppConfigTest` |
| 7. Мультипользовательский режим | Владелец записан в ссылке (`ownerId`), `list` показывает только свои ссылки, их может быть сколько угодно | `LinkServiceTest`, интеграционные сценарии |
| 8. Уведомления | `Notification` создаётся в момент последнего разрешённого перехода и при удалении просроченной ссылки; хранится до прочтения, показывается после каждой команды и при `login`, переживает перезапуск | `LinkServiceTest`, `ConsoleAppTest`, сценарий «непрочитанные уведомления после перезапуска» |
| 9. Редактирование | `edit-limit` доступна владельцу и только для действующей ссылки; диапазон от «переходы + 1» до `link.max-limit` показывается в `list` и в тексте ошибки; проверки выполняются внутри атомарного `update` | `LinkServiceTest`, `CommandProcessorTest` |
| 10. Ошибки и устойчивость | `UrlValidator` (http/https, хост, до 2048 символов), границы лимита, строгий UUID; ошибка ввода печатается и работа продолжается; непредвиденные ошибки перехватывает цикл консоли; повреждённый файл данных останавливает запуск без потери данных | `UrlValidatorTest`, `JsonFileStoreTest`, `ConsoleAppTest` |
| 11. UX консоли | `help`, подсказки «Использование: …», понятные русские сообщения, баннер при выдаче UUID, подсказка диапазона лимита в `list`, пример сеанса в README | `CommandProcessorTest`, `MessagesTest` |
| 12. Тестирование | 179 тестов: модульные на каждый класс и интеграционные (`ConsoleAppTest`, `ShortenerScenariosTest`) | `./mvnw test`, CI |
| 13. Архитектура | Слои `core / infra / ui`, интерфейсы в `core`, реализации в `infra`, зависимости передаются через конструкторы и собираются в `Main`; время через `Clock` | Раздел «Архитектура», `docs/ARCHITECTURE.md` |
| 14. Документация | Этот README (установка, команды и пример, архитектура и решения, тестирование) и описание каждого модуля в `docs/ARCHITECTURE.md` | — |
| 15. Автоматизация | GitHub Actions (`.github/workflows/ci.yml`): `./mvnw verify` — сборка, тесты и проверка стиля; Spotless и `.editorconfig` | Значок CI вверху страницы |

## Если что-то пошло не так

- **Русские буквы отображаются неверно** (например, в терминале IntelliJ): выполните перед запуском `chcp.com 65001` (Git Bash) или `chcp 65001` (cmd, PowerShell) либо запустите программу в отдельном окне Git Bash.
- **Команда `java` не найдена:** добавьте папку `bin` вашего JDK 21 в переменную `PATH` или запускайте по полному пути к `java`.
- **Браузер не открылся:** программа выведет адрес, откройте его вручную. Переход при этом засчитан.
- **Сообщение о повреждённом файле данных:** исправьте или удалите файл из `data/`, который назван в сообщении.
- **Не запускайте две копии программы на одной папке `data/`:** файлы рассчитаны на один процесс.
