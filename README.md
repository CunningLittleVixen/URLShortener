## Конфигурация

Параметры приложения хранятся в отдельном файле
[`src/main/resources/app.properties`](src/main/resources/app.properties).
Значения читаются при запуске, в коде они не прописаны.

### Параметры

| Параметр | Назначение | Значение по умолчанию |
|----------|-----------|-----------------------|
| `link.ttl` | Время жизни ссылки. Задаётся только в конфигурации, пользователь его изменить не может | `PT24H` (24 часа) |
| `link.min-limit` | Минимально допустимый лимит переходов | `1` |
| `link.max-limit` | Максимально допустимый лимит переходов | `1000` |
| `link.default-limit` | Лимит переходов, если пользователь не указал свой | `1000` |
| `link.code-length` | Длина короткого кода | `6` |
| `link.prefix` | Префикс, который отображается перед кодом в короткой ссылке | `clck.ru/` |
| `cleanup.interval` | Как часто удаляются просроченные ссылки | `PT1M` (раз в минуту) |
| `storage.file` | Путь к файлу с данными (JSON) | `data/links.json` |

### Формат времени

Время жизни и интервал очистки записываются в стандартном формате длительности
ISO-8601: `PT` и далее число с единицей измерения.

- `PT24H` - 24 часа;
- `PT1H` - 1 час;
- `PT30M` - 30 минут;
- `PT30S` - 30 секунд.

### Как изменить настройки

1. Откройте `src/main/resources/app.properties` в текстовом редакторе.
2. Измените нужные значения, например `link.ttl=PT1H`.
3. Пересоберите и запустите приложение. Файл копируется в сборку при компиляции,
   поэтому изменения применяются только после пересборки.

### Проверка значений

Конфигурация проверяется при запуске. Приложение не запустится и сообщит о причине,
если:

- отсутствует обязательный параметр или его значение пустое;
- время или число записано в неверном формате (например, `link.ttl=сутки`);
- время жизни или интервал очистки не положительные;
- минимальный лимит меньше 1 или максимальный лимит меньше минимального;
- лимит по умолчанию выходит за границы между минимумом и максимумом;
- длина кода меньше 1.


## Архитектура

Проект разделён на слои, чтобы бизнес-логика не зависела от способа хранения
данных и от интерфейса.

- `core` - модель и контракты: `Link` (ссылка), `AppConfig` (конфигурация),
  `LinkRepository` (интерфейс хранилища). Слой ничего не знает о файлах и консоли.
- `infra` - реализации для внешнего мира: `ConfigLoader` (чтение
  `app.properties`), `InMemoryLinkRepository` (хранилище в памяти).
- `ui` - консольный интерфейс (будет добавлен позже).

### Принятые решения

- Модель `Link` и `AppConfig` - неизменяемые `record`: объект нельзя случайно
  изменить, обновление создаёт новую копию.
- Состояние ссылки (просрочена или исчерпан лимит) не хранится, а вычисляется
  из данных: статус не может разойтись с реальностью.
- Текущее время передаётся в методы параметром, поэтому поведение по времени
  проверяется тестами без ожидания.
- Пользователь определяется UUID владельца в ссылке, отдельного списка
  пользователей нет.
- Уникальность кода ссылки обеспечивает атомарная операция
  `LinkRepository.add`.
