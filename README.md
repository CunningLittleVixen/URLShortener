## Конфигурация

Параметры приложения хранятся в отдельном файле
[`src/main/resources/app.properties`](src/main/resources/app.properties).
Значения читаются при запуске, в коде они не прописаны.
Файлы, где хранятся ссылки `storage.file`  `data/links.json`
Файлы, где хранятся непрочитанные уведомления. `storage.notifications-file`  `data/notifications.json`  Должны отличаться от `storage.file` 

### Параметры

| Параметр | Назначение | Значение по умолчанию |
|----------|-----------|-----------------------|
| `link.ttl` | Время жизни ссылки. Задаётся только в конфигурации, пользователь его изменить не может | `PT24H` (24 часа) |
| `link.min-limit` | Минимально допустимый лимит переходов | `1` |
| `link.max-limit` | Максимально допустимый лимит переходов | `1000` |
| `link.default-limit` | Лимит переходов, если пользователь не указал свой | `1000` |
| `link.code-length` | Длина короткого кода | `6` |
| `link.prefix` | Префикс, который отображается перед кодом в короткой ссылке | `clck.ru/` |
| `cleanup.interval` | Как часто удаляются просроченные ссылки | `PT1M` (раз в минуту) |
| `storage.file` | Путь к файлу с данными (JSON) | `data/links.json` |

### Формат времени

Время жизни и интервал очистки записываются в стандартном формате длительности
ISO-8601: `PT` и далее число с единицей измерения.

- `PT24H` - 24 часа;
- `PT1H` - 1 час;
- `PT30M` - 30 минут;
- `PT30S` - 30 секунд.

### Как изменить настройки

1. Откройте `src/main/resources/app.properties` в текстовом редакторе.
2. Измените нужные значения, например `link.ttl=PT1H`.
3. Пересоберите и запустите приложение. Файл копируется в сборку при компиляции,
   поэтому изменения применяются только после пересборки.

### Проверка значений

Конфигурация проверяется при запуске. Приложение не запустится и сообщит о причине,
если:

- отсутствует обязательный параметр или его значение пустое;
- время или число записано в неверном формате (например, `link.ttl=сутки`);
- время жизни или интервал очистки не положительные;
- минимальный лимит меньше 1 или максимальный лимит меньше минимального;
- лимит по умолчанию выходит за границы между минимумом и максимумом;
- длина кода меньше 1.

## Переходы и лимит

- Каждый переход по короткой ссылке увеличивает счётчик на 1. Подсчёт атомарный:
  при одновременных переходах ни один не теряется.
- Переход засчитывается в момент выдачи адреса, даже если браузер потом не открылся.
- Ссылку можно вводить как `clck.ru/aB3xYz` или просто `aB3xYz`. Регистр символов важен.
- Ссылка недоступна, если истёк срок жизни или исчерпан лимит переходов. Если причин две,
  сообщается об истёкшем сроке.
- Недоступная ссылка не удаляется сразу: она хранится до окончания срока жизни,
  затем удаляется автоматически. Заблокированный переход счётчик не увеличивает.
- Открыть ссылку по коду может любой, в том числе гость.

## Срок жизни ссылок и автоудаление

- Срок жизни задаётся программно в `app.properties` (`link.ttl`, по умолчанию `PT24H`,
  то есть 24 часа) и одинаков для всех ссылок. Пользователь его изменить не может.
- По истечении срока переход по ссылке блокируется сразу, не дожидаясь очистки.
- Просроченные ссылки удаляются автоматически фоновым процессом: первый раз при старте,
  затем через каждые `cleanup.interval` (по умолчанию `PT1M`) после окончания предыдущего прохода.
- Ссылки, у которых исчерпан лимит переходов, не удаляются сразу, а хранятся до окончания
  срока жизни, после чего удаляются так же, как остальные.
- Фоновый поток очистки является демоном и не мешает завершению программы; при выходе
  из приложения он останавливается корректно и ждёт окончания текущего прохода.

## Пользователи и права

- Пользователь идентифицируется только по UUID, пароля и роли администратора нет.
  UUID выдаётся при первой команде `create` и действует до конца сеанса; после
  перезапуска нужно войти командой `login <uuid>`.
- У одного пользователя может быть сколько угодно ссылок. Разные пользователи получают
  разные коды даже для одного и того же URL.
- Менять лимит и удалять ссылку может только её владелец. Открыть ссылку по коду может
  любой, в том числе гость.
- Лимит можно менять только у действующей ссылки (не исчерпанной и не просроченной).
  Новый лимит должен быть больше текущего числа переходов и не больше `link.max-limit`.
  Срок жизни при этом не продлевается, а счётчик переходов не обнуляется.
- Удалить свою ссылку можно в любом состоянии.
- Команда `list` показывает все ваши ссылки по порядку создания и статус каждой:
  «действует», «лимит исчерпан» или «срок истёк» (до автоудаления).

## Уведомления

- Владелец ссылки получает уведомление в двух случаях: когда исчерпан лимит переходов
  (в момент последнего разрешённого перехода) и когда ссылка удалена автоочисткой после
  истечения срока жизни. Если лимит был исчерпан раньше, придёт два уведомления.
- Уведомления хранятся, пока владелец их не прочитает. Они показываются при входе
  (`login <uuid>`) и после каждой команды активного пользователя, после показа удаляются.
- Если у пользователя не осталось ссылок, а уведомления прочитаны, его UUID считается
  неизвестным: чтобы продолжить, выполните `create` (будет выдан новый UUID).
- Если владелец удаляет ссылку сам, уведомление не создаётся.
- Ограничение: если владелец не входит в приложение, его непрочитанные уведомления
  остаются в хранилище.
- UUID при входе должен быть записан полностью (36 символов), например
  `123e4567-e89b-12d3-a456-426614174000`.

## Архитектура

Проект разделён на слои, чтобы бизнес-логика не зависела от способа хранения
данных и от интерфейса.

- `core` - модель и контракты: `Link` (ссылка), `AppConfig` (конфигурация),
  `LinkRepository` (интерфейс хранилища). Слой ничего не знает о файлах и консоли.
- `infra` - реализации для внешнего мира: `ConfigLoader` (чтение
  `app.properties`), `InMemoryLinkRepository` (хранилище в памяти).
- `ui` - консольный интерфейс (будет добавлен позже).

### Принятые решения

- Модель `Link` и `AppConfig` - неизменяемые `record`: объект нельзя случайно
  изменить, обновление создаёт новую копию.
- Состояние ссылки (просрочена или исчерпан лимит) не хранится, а вычисляется
  из данных: статус не может разойтись с реальностью.
- Текущее время передаётся в методы параметром, поэтому поведение по времени
  проверяется тестами без ожидания.
- Пользователь определяется UUID владельца в ссылке, отдельного списка
  пользователей нет.
- Уникальность кода ссылки обеспечивает атомарная операция
  `LinkRepository.add`.
